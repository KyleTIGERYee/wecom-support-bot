# 测试缝（seams）

按 tdd skill 要求，测试只写在这些经过确认的公开边界上，不测内部实现细节。

| 缝 | 模块 | 公开签名 | 验证的行为 |
|---|---|---|---|
| S1 命令白名单 | `src/command-whitelist.js` | `isCommandAllowed(command, roots) → {allowed, reason}` | 合法脚本放行；写入、外传、越界路径、读凭证全部拒绝 |
| S2 Agent 调用 | `src/agent.js` | `runAgentTurn({prompt, sessionId, runner, timeoutMs, idleTimeoutMs, hardTimeoutMs, thinkingLevel, config, projectDir, resourceCatalog?, currentSkill?}) → {text, biTouched, timedOut, stalled, failed, inputTokens, contextInsufficient, loadedResources, executionApprovals}` | 从事件流提取最终答复；仅直接 python/python3 首参为 bi_query.py 且成功结束的命令按 toolCallId 置 biTouched，合法引号/转义/拼接可识别，展开或无法解析及 echo、文字参数、DENY、失败均不算；事件流持续吐时不超时；静默超过 idle 判 stalled；超过 hard 判 timedOut；回传输入 token 数；思考强度透传给 runner；识别概念内容不足信号；记录目录内成功完成的 read 及资源类型/深度；传递真实当前 Skill 并公开脱敏审批摘要 |
| S3 守卫判定 | `src/guard.js` | `reviewReply({answer, callModel}) → {verdict, reason}` | ALLOW/DENY 解析；模型故障时 fail-closed；只判答复、不接收提问 |
| S4 轮次编排 | `src/orchestrate.js` | `handleTurn({question, sessionKey, deps}) → {finalText, rounds, guarded, exhausted, timedOut, stalled, stallRetries, currentSkill, loadedSkills, loadedResources, executionApprovals, loadDepth}`；`deps.context` 提供薄资源目录、查数手册可用性及 Skill 元数据 | DENY 后重写一次即通过；连续 3 次 DENY 走兜底；未碰 BI 时不调用 guard；卡住自动重试一次，仍卡住给超时话术；简单概念不强制 raw，具体规则按概念内容充分性深化，查数按需读手册；知识与 Skill 共用任务路由，命中后读取真实正文且按需深入引用；公开实际加载来源、时间、Skills、引用资源、审批结果与最深深度 |
| S5 会话标记 | `src/session-state.js` | `createSessionState({storePath, rotation}) → {resolveSessionId(userKey, now), recordActivity, startNewSession, markBiTouched, isBiTouched, flush}` | 跨进程重启保留；文件损坏时保守地全量过 guard；会话满 24 小时 / 闲置满 24 小时 / 上下文超阈值自动换代；老状态文件首次访问换一次；旧代粘性标记随之作废 |
| S6 收件箱 | `src/inbox.js` | `createInbox({storePath}) → {load, accept(msg) → {isNew}, markRunning, markAnswered, markFailed, recoverable(now, windowMs) → msg[], stale(now, windowMs) → msg[], compact, flush}` | 同 msgid 只接受一次；重启后读回未答问题；超出窗口不返回；坏行不崩；清理按保留期丢记录 |
| S7 投递 | `src/deliver.js` | `deliverFinal({text, stream, push, retries, wait}) → {channel, reason?}` | 流式成功走 stream；流式失败改走 push；push 按次数重试；全失败返回 none 且不抛异常 |
| S8 两段式生命周期 | `src/turn-lifecycle.js` | `runTurnLifecycle({execute, surface, messages, slowAfterMs, handoffAfterMs}) → {mode, text, result}` | 快答不发提示；慢了一次慢提示；超交接时限先收尾再返回后台答案；执行失败异常上抛；交接后不再重复提示 |
| S9 会话队列 | `src/session-queue.js` | `createSessionQueue({maxConcurrent}) → {run(key, fn)}` | 同 key 按到达顺序串行；不同 key 并行；总并发不超上限；任务抛异常后队列继续 |
| S10 分级路由 | `src/route.js` | `classifyQuestion({question, callModel}) → "quick"\|"deep"` | QUICK/DEEP 正确解析；夹带解释取首个关键词；无法识别或模型故障一律 deep |
| S11 图片下载 | `src/images.js` | `downloadImages({client, images, dir, msgid, maxBytes}) → string[]` | 下载解密后落盘并返回路径；超限拒绝；非常见后缀归一为 .jpg；多张按序号命名 |
| S12 消息归一化 | `src/wecom.js` | `normalizeMessage(frame) → {text, userId, chatType, chatId, msgid, images} \| null` | 文本/语音/图文混排提取文字；纯图与混排取图；无文字且无图返回 null；会话指令识别与 @提及剥离 |
| S13 执行审批 | `extensions/bash-whitelist.ts` | 真实 pi `tool_call` 钩子：write/edit/bash → 放行或 `{block, reason}`；`processApprovedToolCall({event, task, callModel, execute, ...}) → {verdict, source, reason, riskCategory, executionResult?}` | ALLOW 后执行；DENY 理由回主 Agent；硬规则不可被模型覆盖；异常、超时、无效输出 fail-closed；逐次审批不扩散；写目标限写根，cp 源限读根，mv 源与目标均限写根且避开保护根；本地可信 BI 的候选、写根、保护根统一按真实路径排除，符号链接别名与悬空路径 fail-closed，外部环境变量不能自行增加入口；默认企微只读 |
| S14 本地实例公开工作流程 | `scripts/local-instance.js` | `npm run instance -- init|ask|sync|status|export|configure-bi|inventory|plan|sync-due|schedule [选项]` → JSON 结果 | 目录、文件、zip 与本地/file/HTTP(S)/SSH GitLab 来源的单向复制；团队/空白/导入模板；四模型连接测试与真实 pi 配置；知识、Skills、04 执行审批与示例任务逐项真实检查；事务式同步保留 workspace、会话和运行状态；团队包不含凭证、私人来源与运行状态（发现敏感文件时拒绝导出）；status 公开资源版本、目录一致性、副本漂移、最近同步、加载失败和实际覆盖；知识正文仅访问本地副本，任务文件仅访问独立 workspace，saved.trustedDataScripts 只登记按业务线只执行且不可读的 BI 适配器，configure-bi 仅登记默认业务目录的真实 bi_query.py 且不改 ready、资源、workspace 或会话；现有 Guard 重写保持可用 |
| S15 Windows/WSL2 公开工作流程 | `scripts/windows-instance.js`、`windows/install.ps1`、`windows/console.ps1`、`windows/linux/*.sh` | `npm run windows -- install-plan|build-package|...|state-merge|cutover-*|rollback-* [选项]` → JSON；控制台与安装脚本退出码 | 标准包布局、白名单及哈希；安装参数、安全门与 WSL 命令计划；统一 runtime pi 环境；systemd 单元及假 systemctl/launchctl 启停顺序；本地实例企微配置；固定场景结构化 JSON 证据、独立测试 botId、人工复核与固定问题正文 SHA-256 硬门；dry-run 切换/回滚；无秘密的 inbox、根/嵌套会话和任务状态无损合并与失败安全停止 |
| S16 频率与盘点模型 | `src/sync-plan.js`、`src/instance-inventory.js`、`src/source-spec.js` | `CADENCE_KINDS`、`normalizeCadence`、`cadenceText`、`isDue`、`nextDueAt`、`buildSchedule`；`createPathFilter`、`createSourcePathFilter`、`isSensitiveName`、`DEFAULT_EXCLUDES`、`SECRET_EXCLUDES`、`scanInventory`；`normalizeSource`、`canonicalSourceKey`、`findRegisteredSource`、`assertUniqueSourceNames` | `CADENCE_KINDS` 与 `normalizeCadence` 接受集合一致（hourly 是 every 60 的糖，缺 `everyMinutes` 不报错）；`weekdays` 对 every/daily/weekly 生效，kind 分派只在一处、`cadenceText`/`isDue`/`nextDueAt` 共用同一次求值；systemd timer 含 `OnBootSec`/`OnActiveSec`/`Persistent=true`；过滤规则对最终真实目标生效且复制与盘点共用；盘点接受 `--exclude`/`--symlinks`，`files`/`bytes` 与实际复制量同义，`totalFiles` 为排除前总量，敏感目标计数；含 userinfo 的盘点根直接拒绝且不回显凭证；来源身份按 realpath 精确匹配 registry，同一实例内来源名必须唯一 |
| S17 安装前检查 | `scripts/setup.js` | `npm run setup -- [--check] [--allow-install]` → `{status, readyToInit, node, dependencies, pi, tools}`，每项 `{status, version, action, note}` | 固定输出 JSON；任何失败路径都输出完整六项形状。Node 低于 `engines.node` 直接失败并给升级命令，其余检查仍如实报告；缺依赖或 pi 时未给 `--allow-install` 只报告不安装；同意后执行 `npm install` / `bash scripts/install-pi.sh`，并复验 `pi --version` 可执行，失败即失败；`--check` 不安装；python3/zip/unzip 缺失只报告并说明 BI / 资源包能力影响；`readyToInit` 只由 node + dependencies + pi 决定 |

S14 公开签名覆盖 `inventory|plan|sync-due|schedule`：`inventory` 的 kind/kinds、totalFiles/files、sensitive、exclude/symlinks 与 recommended；`plan` 的 `manual|every|hourly|daily|weekly`、`weekdays`、`--exclude`/`--clear-excludes` 与 `--symlinks follow|skip|reject`，`--source` 按 registry realpath 精确匹配；`sync-due` 的整包来源集合与 `removed`；`schedule` 默认 dry-run（`--dry-run` 与默认行为等价）与 `--install/--uninstall` 的 `--yes` 同意闸门。`sync` 与 `sync-due` 结果都公开 `previousVersion`、`snapshotPath`、`localModifications`；`sync` 另公开 `notIncluded`（计划中应同步但本次未复制的来源）。`plan`/`status` 公开 `nextDueAt`，复制结果公开 `excludedSensitive {files,total}`。`status` 的 `localModifications` 是当前 `context/` 相对已同步基线的实时漂移，`lastSyncLocalModifications` 是上一次同步当时的报告，两者分开；`plan` 对使用 `--include-secrets` 的来源公开 `secretsIncluded` 与 `secretFiles`。`init`/`sync`/`plan` 支持逐来源 `--include-secrets`（仅 `private`，`shared` 直接报错），只要使用就标 `secretsIncluded: true` 并列出 `secretFiles`（无命中时为空数组）；`export` 发现敏感文件时报错拒绝，不静默剔除。`init`/`sync` 还接受逐来源 `--exclude`/`--clear-excludes`/`--symlinks`（与 `plan` 同义），写入 registry 并在首次补齐计划时沿用。原始来源路径、类型、`--ref` 与登记期复制选项只写入实例内 `data/source-registry.json`（mode 0600），`--ref` 不复制进 `instance.json` 的 `contextSources`，也不进入团队包；registry 与 context、instance.json、sync-status、`snapshots/previous`（先暂存为 `previous.next`，提交成功才替换）同事务提交，失败全部回滚并保留旧快照。

S14 不新增内部函数测试缝：测试只驱动公开 CLI，以临时目录和本地假 OpenAI 兼容服务替代外部模型；GitLab HTTP/SSH 通过 PATH 中的假 git 验证 clone 参数、临时副本、失败清理与凭证脱敏，不访问真实远端。真实 pi 查数验收通过现有 binary 注入点运行本地实例模式，在临时实例 `instance.json` 的 `saved.trustedDataScripts` 中登记隔离的“只执行、不可读”假 BI 适配器，不访问真实 BI。原先的“默认只读模式 + 重定位扩展副本”只是旧测试装置，现由 saved 配置适配器替代；这不扩大知识读取边界，知识正文仍只能读本地副本，适配器脚本、凭证和原目录其他文件仍不可读。公开回归必须保持副本同名 `bi_query.py` DENY、写根/保护根符号链接别名与悬空路径 fail-closed、外部环境变量白名单无效；父进程只把 saved 派生的按业务线执行入口传给 prompt 和扩展。真实 pi 文档验收仍逐次验证 write/edit 审批。本机存在隔离 pi 时，同时使用真实 pi binary 验证模型配置、文件白名单、文档产物与查数组合，不存在时仅跳过对应真实 pi 验收。S13 使用真实 TS 扩展公开 `tool_call` 行为，并以临时目录、本地假模型和假执行器覆盖执行结果，不访问真实企微、生产或主工作区。

S15 不新增内部函数测试缝：测试只驱动上述公开 CLI/脚本，以临时目录、假 systemctl/launchctl、假 WSL/进程边界验证命令顺序和安全门。macOS 的 dry-run、静态检查与假边界结果不得写成真实 Windows、WSL2、systemd、模型网络、企微或正式切换已通过；这些实机项目固定列入 `docs/windows-wsl2.md` 的未验收清单。

依赖注入约定：S2 的 `runner`、S3/S10 的 `callModel`、S4 的 `deps`、S7 的 `stream`/`push`/`wait`、S8 的 `execute`/`surface`、S11 的 `client` 都是注入点，测试用假实现替换真实的外部边界（子进程、HTTP、企微 SDK、时钟）。项目自身模块一律不 mock。

不写单测、靠冒烟验证的部分：单实例锁的 pid 探活、SIGTERM 优雅退出的等待、launchd 配置、启动补跑的实际拉起、提示词拆分的效果（靠 `docs/regression-questions.md` 前后对比）。
